**实现方式（纯代码，未用 Dify 等低代码平台）**，全链路在仓库 `app/` 内，仅依赖基础库：

- 数据流：PDF(2x render) → macOS Vision OCR（行级→坐标框级两轮）→ 双栏重构 → 词条切分（正则+注音）→ 术语规范化（注音反查）→ `chunks.jsonl`（620 块 = 549 词条 + 59 章节块 + 12 视频块）；视频侧 yt-dlp 取音轨 + whisper.cpp small 本地转写（315 段，覆盖 98.9%）。

## 开源 RAG 方案选型及理由

- **自研纯代码而非 Dify/LangChain 编排**：题目要求纯代码实现；检索、上下文组装、生成、引用映射、评测全链路自写（约 2k 行核心代码），行为完全可审计可复现。
- **OCR = macOS Vision**：本机实测行级/坐标框级两轮质量优于 tesseract-jpn（对照实验见 `reports/source_audit.md`）。
- **转写 = whisper.cpp**：python 绑定（openai-whisper / faster-whisper / whisper.py）三条兼容链全部失败后改用 C++ 版，本地 small 模型零依赖跑通。
- **检索 = BM25 + FAISS 混合而非单路**：最终集（n=54 可答题）真实对照：

| 组 | Recall@5 | MRR@5 | Hit@5 | 延迟 |
|---|---|---|---|---|
| C BM25 | 0.8256 | 0.7614 | 0.9074 | 0.6ms |
| B 向量 | 0.4059 | 0.4877 | 0.5000 | 8.3ms |
| **D 混合 α=0.3** | **0.8596** | **0.7793** | **0.9444** | 8.7ms |
| E 混合+CE 重排 | 0.6667 | 0.4222 | 0.7593 | 638.5ms |

  - 纯向量不可用：中文问→日文词条跨语场景，MiniLM 嵌入显著弱于 BM25 字符 bigram（recall 0.41 vs 0.83）；纯 BM25 非最优：向量腿非零信号以 0.3 权重并入后三指标全面超越；英文 CE 重排跨语有害（见失败案例 5）。
  - α=0.3 由 dev 集（22 可答题）扫描选定（MRR 0.644/**0.736**/0.693/0.646/0.409），final 集单次使用未再调参。
- **rank-bm25 / faiss-cpu / sentence-transformers**：零服务依赖的本地组合，无需向量数据库——620 块规模下 FAISS 平铺索引检索 8ms，引入外部服务属过度设计。
- **服务 = FastAPI + uvicorn + 单页前端**：最小可部署；公网 cloudflared quick tunnel（免账号零配置）。
- **生成 = glm-4-flash**：OpenAI 兼容、免费档，适合评测大量调用（60 题×2 组答案层实验零成本）。

## 评估方案设计及理由

**题集设计**：dev 30 题（调参，α 扫描只在其上做）/ final 60 题（单次使用后未再调参）——分集防调参泄漏。final 题型覆盖题目要求的四类：

| 题型 | 数 | 对应要求 |
|---|---|---|
| term_def / term_contrast | 24 / 13 | 正常检索 + 容易混淆的问题（原画/動画/レイアウト 职责互混） |
| process_flow / multi_chunk | 10 / 6 | 跨段落问题（上下游交接需拼多块证据） |
| insufficient / out_of_scope | 4 / 3 | 知识库外问题（拒答测试） |

**锚点设计**（关键决策）：每题判分要点 = 日文原文锚串 + OCR 变体注记，质检程序验证 90 题 100% 要点可回溯证据原文（unsupported=0）。理由：OCR 有系统性误读（原面=原画），若锚点用「正确写法」会误判检索失败；引文必须引用误读原文并注记变体，严格口径才可信。

**指标设计**：检索层 Recall@5 / MRR@5 / Hit@5（多证据题按命中比例计 recall；拒答题无证据不计入检索分母）；答案层要点覆盖率（严格锚串）/ 全要点题率 / 拒答正确率 / 引用正确率（引用指向真实命中块比例）。理由：检索质量是 RAG 上限，需独立于生成层测量；引用正确率衡量「可追溯」是否真实成立。

**对照设计**：A 基线（同模型无证据直接回答）vs D 混合RAG（hybrid α=0.3 top-5），同题集、同模型、同生成参数——分离「检索带来的增益」与「模型本身能力」。

**真实结果**（全部真实执行输出，glm-4-flash，60 题×2 组）：

| 指标 | A 基线 | D 混合RAG | 相对变化 |
|---|---|---|---|
| 要点覆盖率（严格锚串） | 0.1132 | **0.3491** | ×3.1 |
| 全要点题率 | 0.0556 | **0.2407** | ×4.3 |
| 拒答正确率（6 库外题） | 0.000（全部硬答/幻觉） | **1.000** | — |
| 引用正确率 | — | 0.6292 | — |
| 平均延迟 | 12.4s | 5.7s | -54% |

- 宽松口径（关键词≥60%）复核：A=0.009 / D=0.264，两种口径结论方向一致；人工抽检 6 题：D 组严格评 0 分中 5 题语义正确——严格分低估 D，真实 RAG 优势只大不小。
- 统计口径如实声明：n=54 可答题（106 要点）+6 拒答题，未做显著性检验，差值为「观察到的提升」。

## 除直接由大模型完成的工作外，自己最耗时的工作

1. **评测集编写与锚点核验（约 50min，最耗时）**：90 道题逐题人工撰写、每题要点逐条到原书页码锚定核对；OCR 误读字符与「正确写法」逐条对照制作变体注记；11 轮修复迭代全部人工驱动。
2. **OCR 质量人工判读（约 40min）**：Vision 与 tesseract 输出逐页对比判读；双栏穿插错位发现（第一轮行级成果报废）；549 词条五十音排序校验规则设计与 210 对违例分类。
3. **失败根因定位（贯穿全程）**：faiss/loky C 级静默段错误（无 traceback，靠二分加载定位）；隧道代理超时（env 代理变量剥离）；这两类问题 LLM 无法直接观测，全靠人工设计实验收缩范围。
4. **交付后双语渲染验证（约 20min）**：零/将等统一汉字字形错误的人工识别与归类（字体栈顺序 + 缺 lang 标注两个根因）；弱模型不遵守行文提示词 → 设计生成层确定性归一化并人工核对多轮 E2E 输出。

## 失败案例分析

5 个完整案例（问题/答案/实际/证据差异/根因/改进/改进前后实测数字）见 `reports/failure_cases.md`，摘要与改进方向：

1. **OCR 词头误读连锁**（原面=原画 等 6 处）：词头误读导致词条边界切错并连锁污染正文。改进：注音反查修复 + `headword_fixed_by_reading` 打标；已修复 6 处，210 序违例人工核验待做。
2. **whisper 同音术语变体**（Lightout=layout、一元=一原、中歌=中割）：转写变体导致 BM25 漏检。改进方向：变体归一表（未做，如实列为待办）。
3. **BM25 长度归一化缺陷**：长释义词条被系统性压分，单元排序测试 FAILED。改进：词头加权 + 归一修正后 PASSED（失败→通过可复现于 tests/test_retrieval.py）。
4. **faiss-loky C 级段错误静默失败**：API 进程内加载 faiss+sentence-transformers 无声崩溃，无日志。改进：向量腿移入 sidecar 隔离子进程（RPC 通信），主进程稳定性实测恢复。
5. **英文 CE 重排跨语有害**：ms-marco-MiniLM-L-6-v2 对日文 query-doc 无判别力，重排后三指标全面劣化（recall 0.86→0.67）且延迟 ×73；首次尝试的 multilingual CE 模型名 404 不可得。改进方向：日文专用 reranker（cl-nagoya）。

交付后新增两类已修复/已知问题：

6. **中日文混排字形错误**（零/将显示为日文字形）：根因=字体栈日文优先 + 统一汉字缺语言标注。改进：默认栈中文优先、`:lang(ja)` 路由、括号内日文原词逐组标注；已上线验证。
7. **弱模型不遵守双语行文提示词**：glm-4-flash 在中文段混入假名读法与日文语法，提示词收紧后仍残留。改进：生成层确定性归一化（删假名读法、新字体映射、顿号转换），pytest 锁定行为（60 passed）。

系统性短板（数字见评估节）：multi_chunk recall 0.62（方向：多跳检索/查询分解）、向量腿跨语弱（方向：日文查询改写、multilingual-e5）、样本 54 未做显著性检验（方向：扩题至 120 或 bootstrap CI）。
