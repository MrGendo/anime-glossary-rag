# Anime Glossary RAG — Layout/原画/動画 职责边界知识库

基于真实资料的动画垂直领域 RAG 系统：以《アニメーションの基礎知識大百科》（神村幸子，224 页扫描书，macOS Vision OCR）与 B 站《从零学动画01》（whisper.cpp 转写）为知识源，验证 RAG 与普通 LLM 在该垂直主题上的差异。

## 快速开始

```bash
# 1. 环境（macOS，已含 uv）
uv venv --python 3.14 .venv 2>/dev/null || uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt

# 2. 数据与索引（仓库已含产物；从零重建则依次运行 scripts/01-…py）
#    核心产物：data/processed/chunks.jsonl（620 块）、data/indexes/vector/

# 3. 测试
.venv/bin/python -m pytest tests/ -q

# 4. 启动服务（Mock LLM 模式，无需 key）
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8902
# 浏览器打开 http://127.0.0.1:8902

# 5. 真 LLM 模式
cp .env.example .env   # 填 ZHIPU_API_KEY（glm-4-flash 免费档）
export ZHIPU_API_KEY=...; 然后同上启动
```

## 回答案例：大模型直接回答 vs RAG 回答

以下为真实实验输出（scripts/81，glm-4-flash，同题集同参数；A=无证据直接回答，D=hybrid α=0.3 top-5）。D 组回答可展开的「引用来源 / 检索证据（含分数）」即 Web UI 上每条回答下的折叠按钮内容，数据完全一致。

### 案例 1：FD-001（term_def）

问题：タイムシート（シート）记录什么？谁在什么时候看它？

A 基线（要点 1/3，答成考勤工时表）：

> タイムシート（シート）は、一般的に時間を記録するための文書やシステムで、以下のような情報を記録します：
> 1. **勤務時間**：従業員がどの時間帯に勤務したかを記録します。
> 2. **休憩時間**：従業員が休憩を取った時間やその長さを記録します。
> …（后接勤怠管理/給与計算/人事総務/外部監査等通用考勤内容，与动画制作无关）

D 混合RAG（要点 3/3，全部命中）：

> タイムシート（シート）は、セルワーク、カメラワーク、撮影特殊効果などが書き込まれる。動面と仕上はこれを見て作業、提影はこれを見ながら撮影する。具体的には、1秒が24分割されている。6秒シートが一般的だが、3秒シートも併用される【E2】。誰がいつタイムシートを見るかについては、知識庫に記載されていないため、回答はできません。

「完整详情」按钮展开内容（D 组检索证据，hybrid 分数）：

| # | chunk | 分数 | 页 | 词条 | 片段 |
|---|---|---|---|---|---|
| 1 | g0325 | 1.000 | p150 | タイムシート | タイムシート（たいむしーと）：（シート）参照。 |
| 2 | **g0252** | 0.667 | p137 | シート | 「撮影伝票」1秒が24分割…セルワーク、カメラワーク、撮影特殊効果などが書き込まれる。動面と仕上はこれを見て作業… |
| 3 | g0169 | 0.362 | p117 | 逆シート | 行き帰りの動きに同じ動のバターンを使うこと… |
| 4 | g0232 | 0.323 | p135 | 撮影 | タイムシート通りに構成し、効果を加え… |
| 5 | g0452 | 0.307 | p185 | フリッカシート | フリッカ的な動きを作るシート操作のこと… |

（证据块即标注题 g0252 p137；D 答案中【E2】被服务层映射回 g0252，模型无法编造来源。）

### 案例 2：FM-004（multi_chunk）

问题：動画マン的职业出路书中怎么说？结合海外出し说明其影响。

A 基线（要点 1/3）：泛泛列出动画公司/游戏公司/广告/教育机构/自由职业等「职业出路」，并把海外出し解释为「扩大影响力、增加收入、文化交流」的正面效应——书中实际内容恰好相反（海外出し导致国内動画职种濒临绝灭），方向性错误。

D 混合RAG（要点 3/3）：引用「90%以上が海外へ出て行く」「国内の動画、仕上栽種は絶話寸前状窓にある」「原画や作監、監督などを輩出するアニメ作りの初期数育的な職種」三个书中要点，结论为海外出し使動画マン国内发展机会减少（引用【E1】【E2】→ g0132 海外出し p108 / g0356 動画 p158）。

检索证据 top-5（hybrid 分数）：g0132 海外出し 0.959（p108）、g0356 動画 0.785（p158）、g0368 動仕 0.438（p162）、g0479 本撮 0.294（p188）、g0369 通写台 0.293（p162）。

### 案例 3：FO-001（库外题，拒答对照）

问题：新世纪福音战士的作画監督是谁？

A 基线（幻觉，硬答）：

> 《新世纪福音战士》的作画监督是庵野秀明。他是该动画的导演，也是作画监督之一……

（庵野是导演而非作画监督——库外知识上连人物职务都编排错。）

D 混合RAG（正确拒答）：

> 证据不足，无法从知识库回答。

检索只命中通用职种词条（作画 0.700 / 作監補 0.454 / 作画監督 0.399——均为职种定义而非具体作品人员），生成层据此拒答。6 道库外/证据不足题 A 组 6/6 硬答（幻觉率 100%），D 组 6/6 正确拒答。

## 检索方式为什么选混合模式（α=0.3）

对比三组候选，最终集（n=54 可答题）：

| 组 | Recall@5 | MRR@5 | Hit@5 | 延迟 |
|---|---|---|---|---|
| C BM25 | 0.8256 | 0.7614 | 0.9074 | 0.6ms |
| B 向量 | 0.4059 | 0.4877 | 0.5000 | 8.3ms |
| D 混合 α=0.3 | **0.8596** | **0.7793** | **0.9444** | 8.7ms |
| E 混合+CE 重排 | 0.6667 | 0.4222 | 0.7593 | 638.5ms |

- 融合公式：score = α·norm(向量) + (1−α)·norm(BM25)，各取 fetch_k=20 候选做 min-max 归一后加权（app/retrieval/hybrid.py）。
- **纯向量不可用**：中文问→日文词条的跨语场景下，MiniLM 多语言嵌入明显弱于 BM25 字符 bigram（recall 0.41 vs 0.83）——向量单独作为主腿会丢一半以上可答题。
- **纯 BM25 不是最优**：向量腿虽弱但非零信号，以 0.3 权重并入后三指标全面超越 BM25 单独（recall +0.034 / MRR +0.018 / hit +0.037），说明两路信号互补而非冗余。
- **重排有害**：英文 ms-marco CE 对日文 query-doc 对无判别力，重排后三指标大幅劣化且延迟 ×73，跨语语料直接套英文 reranker 有害。
- α 选型过程：dev 集（22 可答题）扫描 0/0.3/0.5/0.7/1.0，MRR 0.644/**0.736**/0.693/0.646/0.409，α=0.3 最优后固定，final 集单次使用未再调参。服务端 α 由 RAG_ALPHA 环境变量控制（默认 0.3，app/main.py）。

## 已知限制

- OCR 词头误读（原面=原画 等 6 处已按注音修复并打标）
- whisper 同音术语变体（Lightout=layout、一元=一原、中歌=中割）
- 向量检索在中文问→日文词条场景显著弱于 BM25（见实验结果）
